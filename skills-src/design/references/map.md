# /design map

Generate or refresh `MAP.md` at the repo root: a one-page tour of every per-folder
`.design.yaml` in the repo, with a suggested reading order and links to each folder's
`DESIGN.md`. Pure collation from existing sidecars, no LLM judgment, no reading of
source files. Deterministic and idempotent given unchanged inputs.

Shared conventions (the sidecar schema, the freshness model, which folders qualify)
live in `SKILL.md`. Read that first if you have not.

See `~/newstack/brain/DESIGN_SKILL_SPEC.md` for the system-level context.

## When to use

- After `/design rebuild` reports any folder was rebuilt, since the new shape needs to land in MAP.md.
- Standalone, when onboarding a reader to the repo or refreshing your own mental model.
- Any time. It's cheap. Re-runs against unchanged sidecars produce a byte-identical MAP.md.

## Modes

- Default (no args, run at repo root): regenerate the whole `MAP.md` from all discovered `.design.yaml` files.
- `--print`: emit `MAP.md` content to stdout instead of writing the file. Useful for diff review or piping into other tools.

There is no targeted mode, because `MAP.md` is a whole-repo artifact and a partial map would confuse more than it helps.

## Algorithm

1. **Discover.** Find every `.design.yaml` in the repo, skipping `.git/`, `vendor/`, `node_modules/`, `dist/`, `build/`, `target/`, `.next/`, `__pycache__/`.
2. **Parse.** For each, extract:
   - `package` (folder identity)
   - `purpose` (one-line summary)
   - `language` (e.g. `go`, `ts`, used for the "Languages" stat line)
   - `depends_on:` entries that point at sibling folders in this repo (external paths like `github.com/...` are noted but not part of the internal graph)
3. **Build graph.** Nodes = folders that have a `.design.yaml`. Edges = internal `depends_on` entries.
4. **Topological sort** for the reading order:
   - Roots (in-degree zero) come first, since those are the entry points for a cold reader.
   - Then folders one hop out, then two, and so on.
   - **Cycles:** if a cycle exists, choose a stable arbitrary order for its members (alphabetical by folder path) and report the cycle in a dedicated section so the reader knows the order is partial there.
5. **Render** `MAP.md` with the sections described below. Folder names in the reading-order list and the All-packages table MUST be rendered as markdown links pointing to **that folder's `DESIGN.md`** (`` [`foo/`](foo/DESIGN.md) ``) so the reader can click through. The dependency graph stays in a code block (code blocks don't render links).
6. **Write** `MAP.md` at the repo root (overwriting). Never touch any `.design.yaml` or `DESIGN.md`.

## Output (MAP.md format)

````markdown
# Map

Auto-generated by `/design map`. Do not edit by hand, rerun the skill instead.
Last generated: <ISO timestamp> against HEAD <sha>.
Languages: go (N folders), ts (M folders).

## Suggested reading order

Roots first, with folders that depend on others appearing after their dependencies. Each folder name links to that folder's DESIGN.md.

1. [`events/`](events/DESIGN.md), internal event bus with emit and subscribe primitives
2. [`state/`](state/DESIGN.md), viewport, focus, and per-step mutable state
3. [`notebook/`](notebook/DESIGN.md), cell-based TUI with CRUD safe from any goroutine
4. [`graph/`](graph/DESIGN.md), directed-graph runner with MaxSteps/MaxVisits guardrails
...

## All packages

| Folder | Lang | Purpose |
|---|---|---|
| [`events/`](events/DESIGN.md) | go | internal event bus with emit and subscribe primitives |
| [`state/`](state/DESIGN.md) | go | viewport, focus, and per-step mutable state |
| [`notebook/`](notebook/DESIGN.md) | go | cell-based TUI with CRUD safe from any goroutine |
| ... | ... | ... |

## Dependency graph

```
events/    (no internal deps)
state/     (no internal deps)
notebook/  → events/, state/
graph/     → state/
tui/       → notebook/, graph/
```

## Cycles

(only emitted if any exist, otherwise omit this section)
- [`foo/`](foo/DESIGN.md) ↔ [`bar/`](bar/DESIGN.md) is cyclic. Reading order for these is alphabetical and partial.
````

End the mode with a one-line summary:

```
Wrote MAP.md (N folders, M internal dependency edges, C cycles).
```

If `--print` was passed, print the content to stdout and end with `Printed MAP.md to stdout (no file written).` instead.

## Principles

- **Pure collation.** No LLM judgment on folder content. Everything in `MAP.md` comes from `.design.yaml` sidecars. A shallow purpose gives a shallow `MAP.md`, and the fix belongs at the source rather than here.
- **Whole-repo only.** Partial maps create false confidence (you think you see the dependency graph, when you see half of it). One artifact, always complete.
- **Never edit sidecars or DESIGN.md files.** This mode is one-way: it reads `.design.yaml` and writes `MAP.md`. Going the other direction is `/design rebuild`'s job.
- **Idempotent.** Same inputs → byte-identical `MAP.md`. Re-runs are safe and silent when nothing changed.
- **MAP.md is regenerated whole.** The header says "do not edit by hand" for a reason, since hand edits are lost on the next run. If you want narrative beyond what sidecars provide, put it in `ARCHITECTURE.md` or `README.md`, not `MAP.md`.
- **Missing or malformed sidecars are reported, not silently skipped.** If a `.design.yaml` lacks a `purpose:` or has invalid YAML, list it under "Skipped" at the end of the summary so the user can fix it and rerun.
